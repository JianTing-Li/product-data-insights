# Product Pounce

**Turns messy e-commerce spreadsheets into a prioritized "what needs attention today" list — in seconds, entirely in your browser.**

🔗 **[Try the live demo](https://product-pounce.vercel.app/)** — no signup, no file upload to any server, sample data included.

---

## The Problem

Store managers and e-commerce analysts often pull sales, inventory, and product data from multiple platforms (Amazon, Walmart, Shopify, etc.) as CSV exports — and those exports rarely use the same column names or formats. Today, spotting which products are out of stock, losing money, or tanking in sales means manually cleaning and cross-referencing spreadsheets. Product Pounce automates that: drop in your files, and it tells you exactly which products need a decision and why.

## What Makes It Interesting

- **Privacy by design** — files are processed entirely in the browser and never leave the user's machine. No backend, no upload, no server storage.
- **Smart file matching** — automatically figures out which uploaded file is "products," "sales," or "inventory," and maps inconsistent column headers (e.g. "Qty," "Quantity," "Units") to the right field, ranking its own confidence in each match.
- **Explainable results, not a black box** — every flagged product comes with a plain-language reason (stockout, declining sales, shrinking margin, etc.) generated by a transparent rule engine, not a hidden model.
- **Careful data handling** — datasets are aggregated correctly before being combined, avoiding a common spreadsheet mistake where merging tables silently multiplies revenue numbers.
- **Nothing gets silently dropped** — rows that can't be processed are set aside, labeled, and made inspectable/exportable, so users can trust the output.
- **Designed to be usable, not just functional** — full keyboard navigation, accessible click targets, and a deliberately minimal dashboard (4 key metrics instead of a cluttered chart wall).

## Tech Stack

**React 19, TypeScript, Vite, Tailwind CSS, Zustand, Recharts**

Chosen to keep the whole product client-side and fast: TypeScript catches data-shape bugs before they reach users (critical when parsing unpredictable CSVs), Zustand keeps state management lightweight for a single-page app, and Vite/Tailwind keep the build and UI fast to iterate on solo. Tested with Vitest (unit) and Playwright (end-to-end), reflecting a "ship it, but don't break it" approach even without a team to catch regressions.

## Technical Challenges

- **Matching messy, inconsistent data automatically.** Real-world exports name the same field a dozen different ways. I built a tiered matching system — exact match, then substring, then fuzzy text matching — so the tool works out of the box on files it's never seen, while still flagging low-confidence guesses for the user to check.
- **Avoiding a classic spreadsheet trap.** Naively joining a sales table to a products table can silently multiply revenue if there are duplicate rows. I solved this by aggregating each dataset down to one row per product *before* joining anything — a step that's invisible in the UI but prevents materially wrong numbers.
